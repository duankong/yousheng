# Windows 开黑语音实施计划

**执行方式**　按业务并行开发，使用 superpowers:subagent-driven-development，在同一工作区集成。

**目标**　交付同一安装包内可开服、可加入、支持独立语音频道与文字聊天的 Windows 桌面应用。

**架构和技术**　Vue 3 与 TypeScript 负责展示，Tauri 命令连接 Rust 客户端。Rust 大厅集中管理授权，Axum 与 WebSocket 负责通信，SQLite 保存频道。原生语音使用 LiveKit Rust SDK，开服时启动随包的 LiveKit Server。

**设计依据**　[Windows 开黑语音设计](../specs/2026-11-23-windows-voice-design.md)

## 约束与重点

仅开服时产生主机服务。一次只加入一个频道，删除授权由主机校验，当次聊天留在内存。验证同名或冒名用户、重连后的频道归属、删除与发送同时发生、失去焦点时按键放松、停止大厅时释放音轨和子进程。跨网可达性与 Windows 双机实际音质分别记录。

## 并行任务

- [x] **大厅。** 在 `src-tauri/src/{lobby,channels,chat}` 实现会话、频道持久化、授权及 WebSocket 广播。已用独立身份验证频道创建、越权删除、消息隔离、重启和旧语音凭证失效。
- [x] **语音。** 在 `src-tauri/src/voice/` 实现设备、音轨、发言模式和本地收听。已验证发言条件、逐人音量及静音，并通过真实 LiveKit 双客户端传送可辨认的测试音。
- [x] **桌面界面。** 在 `ui/` 实现开服、邀请、频道聊天、成员音量与设备设置。已通过类型检查、生产构建及实际 WebView2 窗口中的开厅、聊天、删除频道和停服操作。
- [x] **集成与分发。** 已生成 Windows x64 NSIS 安装包，包含桌面程序、LiveKit 服务程序和依赖声明，注册 `duipin://`。实际桌面会话停止后，语音服务进程正常退出。
- [ ] **异地与质量验证。** 验证大厅、信令和音频都可以跨网访问，区分直连和实际中转。五人游戏帧时间、外放回声和家庭网络延迟以对应硬件实测为准。

### 已验证的网络范围

两个独立玩家身份在同一台 Windows 电脑上启动 LiveKit Rust 客户端。主机持续发送 1 kHz 的测试音，访客发送 1.7 kHz 的测试音，双方均从对方音轨解码识别出至少 100 毫秒的匹配信号。测试同时检查发送和接收的 ICE 候选地址，确认媒体通过访客的 UDP 转发端口。

直连、本机运行的官方中转及 iroh 默认公网共享中转均完成上述测试。公网测试禁用了直接 IP 传输，并读取实际选中的中转路径。两户家庭宽带之间的连通性、真人语音清晰度和五人游戏中的负载尚需实测。

### 已验证的桌面入口

Windows 客户端通过协议参数冷启动能使用已保存的昵称进入邀请指定的大厅。应用已打开时，第二个进程会把邀请转交给原窗口并退出；成员确认后可以切换到新的大厅。两个入口均验证了离线时保留邀请和昵称并允许重试。微信、QQ 或浏览器实际点击分享链接的行为仍待验证。

从安装包解出的 LiveKit Server 与校验过的官方资源逐字节一致。桌面程序与发布构建仅相差 Tauri 写入的三字节 NSIS 类型标记。
